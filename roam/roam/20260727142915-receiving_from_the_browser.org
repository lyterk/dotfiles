This is a known limitation with Yazi as an XDG file chooser. When a browser wants to *save* a file (save dialog), it needs the file chooser to support a "save" mode where you can type a new filename. Yazi's file chooser wrapper typically only handles the *open/pick* mode.

The issue is likely in your file chooser wrapper script. The =xdg-desktop-portal= save dialog passes a =--save= flag or similar, and the script needs to handle it differently.

** Check your wrapper script

Look at your file chooser script (often something like =~/.config/xdg-desktop-portal-termfilechooser= or similar). Find where it calls yazi.

The script needs to handle the save case by letting you *type a filename*. A common fix is to detect the save mode and either:

1. *Use a prompt for the filename* (e.g., with =bemenu=/=wofi=/=fuzzel=) after picking the directory in yazi
2. Use a different tool for save dialogs

** Typical fix

In your chooser script, look for the =--save= or =save= condition and add something like:

#+begin_src bash
if [ "$save" = "true" ]; then
    # Let user pick directory with yazi, then prompt for filename
    dir=$(yazi --chooser-file=/dev/stdout "$startdir" | head -1)
    filename=$(bemenu -p "Save as:" <<< "$suggested_filename")
    echo "$dir/$filename"
fi
#+end_src
