#+title: Secrets to multiple users

* First pass
#+BEGIN_QUOTE
My secrets (SSH key, GPG) are only getting deployed to the `lyterk` user. I think my configuration.nix file is overspecified with a home directory. How can I make this work for a list of users?
#+END_QUOTE


Looking at your configuration, the issue is that =deploySshScript= and =gpgKeyScriptFn= hardcode =${home}= (=/home/lyterk=) and use =chown lyterk:users=.

Here's a refactored approach using functions parameterized by user/homedir:

#+begin_src nix
let
  mkDeploySshScript = { user, homedir }: pkgs.writeShellApplication {
    name = "deploy-ssh-key-${user}";
    runtimeInputs = [ pkgs.coreutils ];
    text = ''
      mkdir -p ${homedir}/.ssh
      rm -f ${homedir}/.ssh/id_ed25519
      ln -sf /run/secrets/sshPrivateKey ${homedir}/.ssh/id_ed25519
      chmod 0600 ${homedir}/.ssh/id_ed25519
      chown ${user}:users ${homedir}/.ssh/id_ed25519
    '';
  };

  mkGpgKeyScript = { user, keyFilename }: pkgs.writeShellApplication {
    name = "deploy-gpg-key-${user}-${keyFilename}";
    runtimeInputs = [ pkgs.gnupg, pkgs.coreutils ];
    text = ''
      ${pkgs.gnupg}/bin/gpg --import /run/secrets/${keyFilename}
      chmod 0700 ~/.gnupg
    '';
  };
in
#+end_src

Then in =systemd.services=, replace the hardcoded services with a generated set:

#+begin_src nix
systemd.services = lib.mkMerge [
  (lib.listToAttrs (map (user: {
    name = "deploy-ssh-key-${user}";
    value = {
      description = "Deploy SSH private key for ${user}";
      after = [ "network-online.target" "sops-nix.service" ];
      wants = [ "network-online.target" ];
      requires = [ "sops-nix.service" ];
      serviceConfig = {
        Type = "oneshot";
        ExecStart = "${mkDeploySshScript { inherit user; homedir = "/home/${user}"; }}/bin/deploy-ssh-key-${user}";
        User = user;
        Group = "users";
        RemainAfterExit = true;
      };
      wantedBy = [ "multi-user.target" ];
    };
  }) [ "lyterk" "work" ]))

  # GPG keys remain lyterk-specific since work likely has different keys
  { deploy-gpg-code-key = { ... }; }
  
  (config.lyterBackups.mkDuplicityUser { ... })
  ...
];
#+end_src

The key changes:
1. *Parameterize* scripts by =user= and =homedir= instead of using the top-level =home= binding
2. *Use =lib.listToAttrs= + =map=* to generate services for each user
3. *Derive homedir* as =/home/${user}= rather than hardcoding it

Note: your =gpgKeyScriptFn= also has a typo — =pkgs.pkgs.writeShellApplication= should be =pkgs.writeShellApplication=.

Yes, here's a cleaner approach using =lib.concatMap= and =lib.listToAttrs= to generate everything declaratively:

#+begin_src nix
let
  users = [
    { name = "lyterk"; homedir = "/home/lyterk"; gpgKeys = [ "gpgCode" "gpgKev" ]; }
    { name = "work";   homedir = "/home/work";   gpgKeys = [ "gpgCode" "gpgKev" ]; }
  ];

  mkSshService = { name, homedir, ... }: {
    name = "deploy-ssh-key-${name}";
    value = {
      description = "Deploy SSH private key for ${name}";
      after = [ "network-online.target" "sops-nix.service" ];
      wants = [ "network-online.target" ];
      requires = [ "sops-nix.service" ];
      wantedBy = [ "multi-user.target" ];
      serviceConfig = {
        Type = "oneshot";
        ExecStart = "${mkDeploySshScript { user = name; inherit homedir; }}/bin/deploy-ssh-key-${name}";
        User = name;
        Group = "users";
        RemainAfterExit = true;
      };
    };
  };

  mkGpgService = { name, ... }: keyFilename: {
    name = "deploy-gpg-${keyFilename}-${name}";
    value = {
      description = "Deploy ${keyFilename} GPG key for ${name}";
      after = [ "network-online.target" "sops-nix.service" ];
      wants = [ "network-online.target" ];
      requires = [ "sops-nix.service" ];
      wantedBy = [ "multi-user.target" ];
      serviceConfig = {
        Type = "oneshot";
        ExecStart = "${mkGpgKeyScriptFn { user = name; inherit keyFilename; }}/bin/deploy-gpg-key-${name}-${keyFilename}";
        User = name;
        Group = "users";
        RemainAfterExit = true;
      };
    };
  };

in {
  systemd.services = lib.listToAttrs (
    lib.concatMap (user: 
      [ (mkSshService user) ]
      ++ map (mkGpgService user) user.gpgKeys
    ) users
  );
}
#+end_src

Key improvements:
- *Single source of truth*: add a user once in the =users= list with their specific GPG keys
- *No repetition*: services are generated, not handwritten
- *Easy to extend*: adding a new user or GPG key is a one-line change in =users

Then, wherever you were using =mkSshService=, replace it with a =sops.secrets= entry:

#+begin_src nix
sops.secrets.sshPrivateKey = {
  owner = "myuser";
  group = "users";

Note: =path= creates a *symlink* at that location pointing to =/run/secrets/sshPrivateKey=. If you need a real file (some tools dislike symlinked SSH keys, though OpenSSH handles them fine), you'd need a tmpfiles rule or activation script instead.

*** Format of the sops file

The =sshPrivateKey= secret should contain the *raw private key file contents* as a multi-line string. In your unencrypted sops YAML:

#+begin_src yaml
sshPrivateKey: |
  -----BEGIN OPENSSH PRIVATE KEY-----
  b3BlbnNzaC1rZXktdjEAAAAABG5vbmUAAAAEbm9uZQAAAAAAAAABAAAAMwAAAAtzc2gt
  ...key contents...
  -----END OPENSSH PRIVATE KEY-----
#+end_src

Key points:
- Use the YAML =|= literal block scalar to preserve newlines.
- Include the trailing newline (OpenSSH requires it).
- After =sops -e=, the value is encrypted but the YAML structure remains.

To add it: =sops secrets.yaml= and paste the key content under =sshPrivateKey:= with =|=.
* Writing one key to multiple files
#+BEGIN_QUOTE
Can I write my sshPrivateKey to multiple files? e.g. to both /home/lyterk/.ssh/id_e25519 and /home/work/.ssh/id_e25519
#+END_QUOTE


No, a single =sops.secrets.<name>= entry can only write to one path. But there are a few ways around it:

** Option 1: Define the same secret twice

#+begin_src nix
sshPrivateKey = {
  owner = "lyterk";
  group = "users";
  mode = "0600";
  path = "/home/lyterk/.ssh/id_ed25519";
};
sshPrivateKeyWork = {
  key = "sshPrivateKey";  # reference the same key in the YAML
  owner = "work";
  group = "users";
  mode = "0600";
  path = "/home/work/.ssh/id_ed25519";
};
#+end_src

The =key= option lets multiple secrets pull from the same entry in your sops file.

** Option 2: Use =system.activationScripts= or a symlink

Point one to the sops-managed file and symlink/copy from the other. But ownership becomes tricky since both users need read access.

** Option 3: Use a shared group

Set =mode = "0640"= and a group both users belong to, then symlink. Less clean since it exposes the key more broadly.

*Option 1 is the idiomatic sops-nix approach.*
