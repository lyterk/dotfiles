** Creating a SOPS Secret for a GitHub Access Token

*** 1. Add the secret to your SOPS secrets file

Your secrets file is likely at =/etc/nixos/secrets/secrets.yaml= (check =shared/sops.nix= for the path). Edit it with:

#+begin_src bash
cd /etc/nixos
sops secrets/secrets.yaml
#+end_src

Add an entry:
#+begin_src yaml
githubToken: ghp_yourActualTokenHere
#+end_src

*** 2. Declare the secret in your sops.nix or configuration

In whichever file declares =sops.secrets= (likely =shared/sops.nix=):

#+begin_src nix
sops.secrets.githubToken = {
  owner = "lyterk";  # or whichever user needs it
};
#+end_src

This makes it available at =/run/secrets/githubToken=.

*** 3. Consume it in your NixOS configuration

For example, passing it to a service as an environment variable:

#+begin_src nix
services.someService = {
  environment.GITHUB_TOKEN = config.sops.secrets.githubToken.path;
  # or for a systemd service:
  serviceConfig.EnvironmentFile = config.sops.secrets.githubToken.path;
};
#+end_src

Or in a shell/script context, reference the path:
#+begin_src bash
export GITHUB_TOKEN=$(cat /run/secrets/githubToken)
#+end_src

*** Key points

- =sops.secrets.<name>.path= gives you the runtime path (e.g. =/run/secrets/githubToken=)
- Never hardcode the token value in nix files — always reference =.path=
- Make sure your =.sops.yaml= key configuration covers the secrets file so it can be decrypted on the target host

The error is in =configuration-base.nix= at this line:

#+begin_src nix
access-tokens = [
  "github.com=${config.sops.secrets.githubToken}"
];
#+end_src

=config.sops.secrets.githubToken= is a *secret attribute set*, not a string. You need to reference its =.path= attribute:

#+begin_src diff
--- a/shared/configuration-base.nix
+++ b/shared/configuration-base.nix
@@ -98,7 +98,7 @@ in
       ];
       access-tokens = [
-        "github.com=${config.sops.secrets.githubToken}"
+        "github.com=${config.sops.secrets.githubToken.path}"
       ];
#+end_src

But wait — =nix.conf= is evaluated at build time, while sops secrets are only available at activation time (runtime). You can't embed a secret file's runtime path into =nix.conf= that way.

The correct approach is to use =nix.settings.access-tokens= with a file reference, or more precisely, use the =extraConfig= option to point to the secret path and let nix read it at daemon start:

#+begin_src diff
--- a/shared/configuration-base.nix
+++ b/shared/configuration-base.nix
@@ -95,9 +95,8 @@ in
     settings = {
       extra-platforms = config.boot.binfmt.emulatedSystems;
       experimental-features = [
         "nix-command"
         "flakes"
         "pipe-operators"
       ];
-      access-tokens = [
-        "github.com=${config.sops.secrets.githubToken}"
-      ];
     };
+    extraConfig = ''
+      !include ${config.sops.secrets.githubToken.path}
+    '';
#+end_src

And in =secrets/githubToken.yaml=, store the content as:

#+begin_src 
access-tokens = github.com=ghp_yourtoken
#+end_src

This way nix daemon reads the token file at runtime after sops has decrypted it.
