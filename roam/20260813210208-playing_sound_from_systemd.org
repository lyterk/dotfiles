*** Diagnosing the Issue

You'd know it's a user/audio issue if you see errors like:
- =ALSA: no soundcards found=
- =Connection refused= (PipeWire/PulseAudio socket)
- The service runs but no audio plays

Check with:
#+begin_src bash
journalctl -u bell.service -f
#+end_src

*** The Core Problem

Audio on modern Linux (PipeWire/PulseAudio) runs as a *user session daemon*. System services run outside that session and can't reach the audio socket at =$XDG_RUNTIME_DIR/pipewire-0= (or pulse equivalent).

*** The Right Solution: systemd User Unit

Yes, a user unit is the correct approach. Here's the diff:

Wait — =loginctl-linger= isn't a NixOS option directly. Use:

#+begin_src diff
+            users.users.${config.services.bell.user}.linger = true;
#+end_src

Actually the correct NixOS option is:

#+begin_src diff
+            systemd.services."user-linger-${config.services.bell.user}" = { ... }
#+end_src

No — the real NixOS option is =users.users.<name>.linger=:

#+begin_src nix
users.users.${config.services.bell.user}.linger = true;
#+end_src

This ensures the user unit starts at boot without an active login session.

*** In your configuration.nix

*** Key Points

- =systemd.user.services= runs within the user's session, inheriting =$XDG_RUNTIME_DIR= and access to PipeWire
- =linger = true= means the unit starts at boot, not just at login
- The =WorkingDirectory= pointing to the nix store is fine since it's world-readable
