Here are some improvements:

#+begin_src nix
refreshConfigScript = pkgs.writeShellScriptBin "refreshNix.sh" ''
  SUDO_PASSWORD=$(${pkgs.rofi}/bin/rofi -dmenu -password -no-fixed-num-lines -p "[sudo] password for $USER: ")
  echo "$SUDO_PASSWORD" | sudo -S ${pkgs.nixos-rebuild}/bin/nixos-rebuild switch --flake /etc/nixos#miranda
'';
#+end_src

Key changes:
- *Removed =zsh=* — =writeShellScriptBin= already uses =bash=, no need to spawn another shell
- *Removed =cd=* — use the absolute path directly in =--flake=
- *Quoted =$SUDO_PASSWORD=* — prevents word splitting issues with special characters
- *Used absolute paths* for =rofi= and =nixos-rebuild= — more robust in keybinding contexts where PATH may be limited

If you want to avoid passing the password via =echo= (slightly safer), you could use =sudo -A= with a =SUDO_ASKPASS= script, but that's more complex.

Add a success notification after the rebuild command using =makoctl= or simply =notify-send= (which mako handles). Here's how:

#+begin_src nix
refreshConfigScript = pkgs.writeShellScriptBin "refreshNix.sh" ''
  SUDO_PASSWORD=$(${pkgs.rofi}/bin/rofi -dmenu -password -no-fixed-num-lines -p "[sudo] password for $USER: ")
  if echo "$SUDO_PASSWORD" | sudo -S ${pkgs.nixos-rebuild}/bin/nixos-rebuild switch --flake /etc/nixos#miranda; then
    ${pkgs.libnotify}/bin/notify-send \
      --urgency=normal \
      --icon=emblem-default \
      "NixOS Rebuild" \
      "Configuration switched successfully ✓"
  else
    ${pkgs.libnotify}/bin/notify-send \
      --urgency=critical \
      --icon=dialog-error \
      "NixOS Rebuild" \
      "Rebuild failed ✗"
  fi
'';
#+end_src

You'll need =pkgs.libnotify= in your packages. The icons (=emblem-default=, =dialog-error=) come from your icon theme — swap them for whatever your theme provides if those don't render.

Notification appearance (background color, etc.) is controlled by your *notification daemon's theme/config*, not by =notify-send= itself. =notify-send= has no color arguments.

*For colors:* configure your notification daemon directly:
- *dunst*: edit =~/.config/dunst/dunstrc= — you can set =[urgency_normal]= and =[urgency_critical]= sections with =background=, =foreground= colors
- *mako*, *swaync*, etc. have similar per-urgency styling

Since you're already using =--urgency=normal= vs =--urgency=critical=, dunst will automatically style them differently if you configure those urgency blocks.

Example dunst config:
#+begin_src ini
[urgency_normal]
background = "#2d8a2d"
foreground = "#ffffff"

[urgency_critical]
background = "#cc2222"
foreground = "#ffffff"
#+end_src

*For icons not rendering:* the icon names are freedesktop standard names that depend on your icon theme having them. Try using absolute paths to actual image files instead:

#+begin_src nix
--icon=${pkgs.gnome.adwaita-icon-theme}/share/icons/Adwaita/48x48/emblems/emblem-default.png
#+end_src

Or just drop the =--icon= flag if you don't need it — the color differentiation via dunst urgency styling is more reliable anyway.
