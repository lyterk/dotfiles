The issue is that =sops-nix= needs the age key to decrypt secrets at activation time, but the key file path =/home/lyterk/.config/sops/age/keys.txt= is in a user's home directory. During early boot (or when running =nixos-rebuild switch= without =--flake=), this path may not be accessible.

** Common fixes:

*1. Move the key to a system path* (most reliable):
#+begin_src nix
sops.age.keyFile = "/var/lib/sops-nix/key.txt";
#+end_src
Then move your key there and ensure permissions are correct (=600=, owned by root).

*2. Use a host SSH key instead of age* (if you have a host ed25519 key):
#+begin_src nix
sops.age.sshKeyPaths = [ "/etc/ssh/ssh_host_ed25519_key" ];
#+end_src
This key exists before any user home directories are mounted.

*3. Keep both* as fallbacks:
#+begin_src nix
sops = {
  age.keyFile = "/var/lib/sops-nix/key.txt";
  age.sshKeyPaths = [ "/etc/ssh/ssh_host_ed25519_key" ];
  ...
};
#+end_src

---

Regarding =nixos-rebuild switch= without =--flake=: without =--flake=, NixOS won't use your =flake.nix= at all, so =sops-nix= module won't be loaded — that's expected behavior and not fixable without using the flake.

The *host SSH key approach* is typically the recommended solution for boot-time reliability.
