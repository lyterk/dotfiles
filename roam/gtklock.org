Yes, that's possible using =pkgs.fetchurl=. Here's how you'd change the background image reference:

#+begin_src nix
let
  lockscreenBg = pkgs.fetchurl {
    url = "https://example.com/lockscreen.png";
    sha256 = "sha256-...";
  };
in
{
  ".config/gtklock/layout.css".text = ''
    window {
       background-image: url("${lockscreenBg}");
       background-size: cover;
       background-repeat: no-repeat;
       background-position: center;
       background-color: gray;
       color: white;
    }
  '';
}
#+end_src

=fetchurl= downloads to the Nix store, so the path will look like =/nix/store/hash-lockscreen.png=.

To get the =sha256=, you can:
1. Run =nix-prefetch-url <url>= to get the hash
2. Or temporarily use =sha256 = lib.fakeHash;=, let it fail, and copy the correct hash from the error message

You'll need =pkgs= in scope — if it's not already available in your =home.nix=, add ={ pkgs, ... }:= to the function arguments.

#+begin_src nix

The =halign=/=valign= directives in CSS blocks are silently ignored — gtklock uses the GTK widget tree for alignment, which you'd control via its config options (e.g., =anchor=, =margin= in the gtklock config), not CSS.

The issue is that =window box= likely doesn't fill the full height, or the alignment isn't set correctly. In GTK/gtklock, you need to explicitly set the box to expand and align its children to the bottom. Try:

#+begin_src css
window box {
  margin: 50px;
  min-height: 100vh; /* or a large value */
  valign: end;       /* this is a GTK property, not standard CSS */
}
#+end_src

However, GTK doesn't use standard CSS flexbox. The GTK-specific approach is to set the =valign= property. But in GTK CSS, positioning is limited.

*More reliable approach* — set the alignment on the box widget using GTK CSS:

#+begin_src css
window box {
  margin: 50px;
}

window > box {
  -gtk-icon-size: 0; /* placeholder */
}
#+end_src

Actually, the most reliable fix for gtklock specifically is to use the =margin-top: auto= trick or ensure the box has =valign = end=. In GTK CSS you can try:

#+begin_src css
window box {
  margin: 50px;
  margin-top: auto;
}
#+end_src

=margin-top: auto= should push the box content to the bottom if the parent is allocating full height. This is the most likely fix — replace your current =window box= rule with:

#+begin_src css
window box {
  margin: 50px;
  margin-top: auto;
}
#+end_src

If that doesn't work, gtklock may require using its module system or the =--gtk-module= flags to control widget placement, as pure CSS has limited layout control in GTK4.
